# HEXAGO

六角形の盤で打つ囲碁風ゲームです。`index.html` 1ファイルに CSS・JS・AI エンジン・写真認識モデルまで全てインライン化された単一ファイル配信のため、GitHub Pages のほか、Google Apps Script（GAS）等の単一HTMLプロキシ経由やローカル環境でもそのまま動きます（ローカル対戦・PeerJS によるオンライン対戦・棋譜保存・連続パス・写真からの盤面復元）。

## ファビコン

3路盤の格子と大きな3色の石（黒・白・赤）を配したアイコンです。

| ファイル | 用途 |
| --- | --- |
| `favicon.ico` | 16/32/48px を内包。Safari や古いブラウザはこちらを優先 |
| `favicon-192.png` / `favicon-512.png` | ブラウザタブ・PWA（角丸あり・透過あり） |
| `favicon-180.png` | iOS ホーム画面用（`apple-touch-icon`）。**透過なし・角丸なし**で書き出す（iOS 側が角丸を付けるため二重になるのを防ぐ） |
| `favicon.svg` | モダンブラウザ用ベクター |
| `favicon-ios.svg` | iOS 用 PNG の元データ（不透過版） |
| `manifest.webmanifest` | ホーム画面アプリ化（`any` / `maskable`） |

`<link>` の順序は Safari 対策で **`.ico` → PNG → apple-touch-icon → SVG** としています（SVG を先頭に置くと Safari が PNG を無視することがあります）。
`index.html` は単一ファイル配信のため、ビルド時にこれらは data URI として埋め込まれます。

アイコンの再生成（要 `npm i -D playwright`）:

```bash
node dev/make-icon-png.js   # 各 PNG → favicon.ico まで一括生成
```

## 遊び方

```bash
python3 -m http.server 8000
# http://localhost:8000/index.html
```

GitHub Pages にリポジトリを置けばそのまま公開できます（リポジトリ直下の `index.html` 1枚がそのまま配信物です）。
PC は交点をホバーしてクリック、スマホは同じ交点を2タップで着手します。
オンライン対戦は PeerJS の公開シグナリングサーバーを使います。

## 対局リプレイと優勢グラフ

終局後（対局中も可）にその対局を**メイン画面の盤面をそのまま使って**再生できます（ポップアップは出ません）。

- **入口**: 終局バナー「リプレイ」 / 結果モーダル「対局をリプレイ」 / 盤面・棋譜モーダル「この対局をリプレイ」
- **画面**: 再生中は盤面の下にある対局用の情報バー（手番・石数・1手戻る/パス/投了）が隠れ、代わりに再生バーと優勢グラフが表示されます。「終了」で元の対局画面に戻ります。
- **再生バー**: 最初へ / 1手戻る / 再生・一時停止 / 1手進む / 最後へ、位置スライダーのドラッグで任意の手へ
- **再生速度**: ×0.5 / ×1 / ×2 / ×4
- **キーボード**: ←/→ で1手移動、Space で再生・一時停止、Esc で終了
- **レイアウト**: 縦画面（スマホ）では盤面の下に再生バーとグラフ、横画面（タブレット・PC横持ち）では**盤面の右にパネルを収めて**配置します。盤面は画面の高さに合わせて自動縮小され、ボタンやグラフが横に伸びすぎることはありません。
- **優勢グラフ**: その時点でどのプレイヤーが優勢かを手単位で可視化。グラフのタップ・ドラッグでその手へ移動でき、最大の形勢変化になった手も表示します。2人戦は1本の対称線、3人以上は各席の線。

### 優勢度の算出（単純な得点計算ではない）

盤面の総点数を分母に固定し、各プレイヤーの持ち点のシェアを出します。

- **石**: そのまま加点
- **確定地**: 一色に囲まれた空点のうち、①囲いが強い（空点領域が小さい）②囲っている石が十分ある③盤が埋まってきた、の3条件を満たす分だけ加点
- **争点**: 複数色に接する空間は、接する石の数で按分（模様・勢力の取り合い）
- **弱石**: 呼吸点1以下（アタリ）の連は取られる可能性として減点
- **未確定の空点**: まだ誰のものでもないので出場者で等分（＝中立）

分母を盤面の総点数に固定しているため、**序盤に石を1つ置いただけではグラフはほとんど動きません**（従来は地＋石の総和で正規化していたため、最序盤にすぐ振り切れていました）。盤面が埋まるほど未確定分が減り、確定分の差がグラフに現れます。

グラフの線色は石の色に合わせつつ、白い石（白背景テーマ）が白地に埋もれないよう自動で視認できる濃さに補正し、ダークテーマでは黒い石を明るめに持ち上げます。

### 対局を共有

リプレイ画面の「共有」ボタン（または結果モーダルの「URLで共有」）から共有できます。

- **URL共有**: 対局の全手を URL の `#` 以降に埋め込みます（`…#g=…`）。**サーバーには何も送信されません**（静的配信のままで動きます）。
  URL を開くとそのままリプレイが開きます。目安は 60手で約700文字、最長の25路盤・500手でも約5,000文字なので、主要ブラウザのURL長制限内です。
- **結果カード画像**: 盤面・優勢グラフ・最終順位をまとめた画像（720×1080）を保存できます。SNSやチャットへの貼り付け向けです。
- **共有シート**: `navigator.share` が使える環境（モバイルのブラウザ）ではOSの共有メニューも使えます。

計算エンジンは `js/core/replay.js`（Node 自己テスト: `node dev/replay-selftest.js`）、UI は `js/ui/replay.js` です。

## 盤面・棋譜の保存と読み込み／連続パス

- **盤面・棋譜モーダル**（ヘッダのフォルダアイコンに統合）:
  - **保存**: 現在の盤面を端末ライブラリへ1タップ保存、または **棋譜 JSON（`hexago-kifu` v1）** / **テキスト（`.txt`）** として書き出し可能
  - **読み込み**: 端末ライブラリに保存した盤面を一覧から即再開できるほか、**棋譜 JSON・保存盤面 JSON のファイル読み込み**、および **📷 写真から盤面を復元** にもここからアクセスできます
- **連続パス**: 対局中の設定モーダル内から席別に ON/OFF できます（設定を閉じると自動パス開始、着手・投了・新規対局で解除）。

## AI

MCTS（モンテカルロ木探索）+ 面積利得評価（`hexago-mcts/2.1.0`）。設定画面で **AI 思考時間** と **AI 棋風（重み）** をそれぞれ切り替えられます：

- **AI のテンポ**（`localStorage` 保存・盤サイズ別に思考時間を自動最適化）:
  - **高速**（既定）: 軽快なテンポで実用的な強さ（最大4並列。強さ曲線の飽和目安に基づき 9路 0.8s / 13路 1.2s / 19路 2.0s / 25路 2.5s を自動適用）。
  - **長考**: じっくり深く読むモード（最大8並列。9路 3s / 13路 6s / 19路 10s / 25路 12s を自動適用）。
- **AI 棋風（重み）**（一括切替＋AIボタンを繰り返しタップで席ごとに個別変更可）:
  - **堅実**: 連結・守り・安全係数重視（無謀な侵入をさらに抑え、堅く地をまとめる）
  - **バランス**: 勝率・攻守の最適バランス
  - **攻撃的**: 切断・弱石攻め・リーダー圧迫・広めの探索重視

全モード・全棋風共通のエンジン特徴：

- **高速なインクリメンタル探索**: プレイアウト内の連・擬似呼吸点・アタリを O(1) で差分管理し、
  純JavaScript（依存なし）のまま 13路で約10,000 playouts/s・25路でも従来の10倍超の速度で深く読みます。
  マルチプライの探索木再利用（2〜6人戦対応）と Progressive Widening により、1手ごとの読みを深く保ちます。
- **2眼確定陣への死に侵入・アゲハマなしの無駄な死に石捕獲を根治**: 実ページの終局採点 `detectDeadStonesSmart` と
  1:1 検証済みの死活判定をルート候補生成に組み込み、①置いた瞬間に死に石除去される手（第3者陣内の既死に石捕獲ループ含む）、
  ②周囲が既に2眼（または1眼＋小ポケット）で生きている敵陣への無謀侵入、③2眼敵陣内に閉じ込められた0眼石への追い打ち、
  ④自陣内の既に死んでいる敵石への無意味な捕獲（HEXAGOはアゲハマなしのため0利得で空所を開けるだけ）を、思考時間や並列数・棋風にかかわらずルート候補から無条件除外します。
- **終盤は「利得」で即断・自陣埋め防止**: 単一領域の安全自陣を2眼化のためだけに埋める挙動を抑止し、他プレイヤーが既にパス宣言済みのときは自陣を埋めずに即パス判断します。全員パス後は AI 戦でも死に石確認フェーズで自動判定結果を確認・修正してから採点できます。
- **人数・盤サイズで重みが変わる**: 3人以上では角・辺からの布石・自石連携とリーダーへの優先攻撃を重視し、
  4人以上は安全係数を引き上げ、生存閾値は盤サイズでスケールします。

思考中は読んだ局面数を表示します。エンジンは `js/ai/engine.js`（Node の自己テスト・ベンチが
直接 require する `dev/ai-engine.js` の同期コピー）で、Web Worker プールで並列に探索します。
エンジンが返すパス判断は最終決定として尊重されます（終盤に際限なく石を置き続けない）。

## 写真から盤面を復元（画像認識AI）

実物の六角盤をスマートフォンで撮影すると、石の配置を読み取って局面として保存できます。
**画像は端末内だけで処理され、外部に送信されません**（APIキー・サーバー不要）。
交点をタップすると「空」と参加中の色を巡回するので、判定違いの石をその場で直せます（iPad などのタッチ端末でも、胴体タップで1段ずつ切り替わります）。
判定が難しい場所は**拡大表示**できます: 2本指ピンチ（PC はマウスホイール）/ ダブルタップ / 「＋ −」ボタンで最大 600% まで拡大し、拡大中は1本指（マウスはドラッグ）で移動できます。拡大したままでもタップで色を修正できます。

使い方:

1. ヘッダの 📷 ボタンを押す
2. 盤全体が写った写真を選ぶ（その場で撮影も可）
3. 自動検出された6隅を確認し、必要なら丸をドラッグして合わせる（盤面サイズは撮影画像から自動判定。違う場合は選び直す）
4. 「この状態で読み取る」→ 写真の石が見える中抜きの色枠で結果が表示される（**枠で重ねる / 並べて比較 / 元写真のみ**で切替可能）
5. 誤判定があればタップして修正（1〜2個直して「修正した石で自動調整」を押すと、同じ色合いの石をまとめて再判定）
6. 「保存」で局面ライブラリへ、「この局面から対局」でそのまま続きから対局

仕組み:

- 盤の外枠を色差＋六角形フィットで自動検出し、6点の homography で正面から見た盤画像（canonical 1024px）に変換
- 交点ごとに 16x16 のパッチを抽出し、28次元の色・形状特徴量を計算
- 小型ニューラルネット（`js/photo/model.json` が学習済みのとき）またはヒューリスティック分類器で「空/黒/白/赤/青/緑/黄/紫」を判定
- 迷った点は琥珀色で示し、タップで必ず正しい状態に直せる（最終的な正解は人が保証する設計）

実写真（13路盤・黒28/白28/青27/空44）での実測:

| 条件 | 交点正解率 | 処理時間 |
|---|---|---|
| 6隅を手動で合わせた場合 | 127/127 (100%) | 約0.1秒 |
| 外枠を自動検出した場合 | 126/127 (99.2%) | 約0.2秒 |

認識モデル:

- 学習データ: 合成盤 2,700枚 / 405,096交点（木目・紙・ダーク・サイバー、三角形格子/六角セル、光沢/艶なし/セミグロス、照明・映り込み・影・ボケ・ノイズ・JPEG劣化をランダム化）
- モデル: 28次元特徴量 → MLP 28-64-32-8（約4,200パラメータ / 83KB / 推論は127点で約7ms）
- 未知シナリオ（学習に無い素材×照明の組み合わせ）での精度: **99.05%**
- 実写真ではヒューリスティック分類器が強い（色かぶり・木目の暖色に頑健）ため、
  「ヒューリスティックが自信を持てた点はそれを使い、迷った点だけモデルと併用する」
  カスケード方式で両方の強みを取っています

対応: 盤面サイズ 9/13/19/25路。読み込み時に **サイズと余白（外枠と格子のすき間）を自動調整**します
（候補を走査して「一致度」が最大になる組み合わせを採用）。実物の盤や印刷の具合でズレるときは、
**余白スライダー**で緑のプレビュー点を石の中心に合わせてください。一致度（%）は常に表示され、
スライダー操作にも追従するので、合っているかどうかがその場で分かります。
色の並び順はそのまま「1P, 2P, …」の割り当てになります。色チップを**ドラッグ&ドロップ**で並べ替えられます
（Pointer Events を使っているので iPad のタッチ操作でも動きます）。チップを2回タップしても2色を入れ替えられます。
誤って追加した色はチップの **×** でプレイヤーから外せます（その色の石は「未使用色＝空点扱い」になり、タップで修正できます）。
実戦ですでに投了しているプレイヤーは「**投了済み**」で指定でき、その局面から対局すると投了済み（`out`）として扱われます。
スマートフォン・iPad（縦横）でもモーダル全体が画面内に収まるよう、盤画像は画面サイズに合わせて自動縮小します。
保存した局面は JSON で書き出し・読み込みできます（`localStorage` の `hexago-photo-lib-v1`）。

## 構成

```
index.html            単一ファイル配信物（dev/build-html.js で生成。GAS プロキシ等でも単体動作）
dev/index.template.html  HTML テンプレート（編集元）
dev/build-html.js     単一ファイル index.html 生成スクリプト（依存なし）
css/app.css           スタイル
js/main.js            起動
js/core/              features（棋譜・連続パス） / theme / sound / geometry / state / rules
js/ai/                engine.js(MCTS) / worker.js / pool.js / heuristic.js
js/ui/                input / render / ui / modals / settings / online / debug
js/photo/             写真復元（geom / features / model(.json) / rectify / detect / recognize / store / ui）
dev/                  開発ツール（自己テスト・E2E・ビルド）
bench/                AI強さベンチマーク
```

開発時はモジュール分割された `css/`・`js/`・`dev/index.template.html` を編集し、`node dev/build-html.js` で単一ファイル `index.html` を再生成します。相対パスのローカルファイル参照を一切持たないため、GitHub Pages のサブパス配信だけでなく Google Apps Script（GAS）等の単一HTMLプロキシ環境でも動作します。

## 開発

```bash
# エンジン同期 & 単一ファイル index.html を生成
node dev/sync-engine.js

node dev/sync-engine.js --check

```

## 注意

- オンライン対戦は PeerJS の公開シグナリングサーバー依存です。
- Web Worker が使えない環境（`file://` や厳格なサンドボックス等）でも、メインスレッドの MCTS エンジンへ自動フォールバックして動作します。
- 写真復元は端末内で完結しますが、写真の撮り方（照明・映り込み・斜め撮影）によって精度が変わります。その場合は6隅のドラッグとタップ修正で必ず正しい局面にできます。
