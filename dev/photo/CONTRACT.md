# 写真→盤面 復元パイプライン 契約（v1）

実物の HEXAGO 盤（六角盤）を撮影した写真から、127/61/271/469 点の石の配置を復元する。
すべてブラウザ内で完結する（外部APIなし・ビルドなし・GitHub Pages 静的配信）。

## 0. 用語

- **盤のサイズ n** ∈ {9, 13, 19, 25}（アプリの `build(n)` と同じ）
- `SIDE = (n+1)/2`, `s = SIDE - 1`（= 六角形の半径をセル数で表したもの）
- 点の総数 = `3*SIDE*(SIDE-1)+1` = 61 / 127 / 271 / 469
- 点の順序はアプリの `build(n)` と完全に同一:
  `for (r = -s..s) for (q = -s..s) if (|q+r| <= s) push([q,r])`

## 1. 正規化盤画像（canonical）

- 正方形キャンバス `W = 1024`
- `pad = 0.07 * W`（= 71.68）
- `cell = (W - 2*pad) / (2*s)`
- 中心 `(W/2, W/2)`
- 点 `(q,r)` の座標:
  `x = W/2 + cell*(q + r/2)`, `y = W/2 + cell*(r*0.8660254037844386)`
- 六角形の6頂点（= 格子の6隅の点）は `(s,0),(0,s),(-s,s),(-s,0),(0,-s),(s,-s)` の座標。

## 2. 写真 → canonical の写像

- 6つの対応点から homography H（3x3, DLT 最小二乗, 12式/8未知）を推定する。
- 対応点は「格子の6隅の点」の画像座標（時計回り: `(s,0),(0,s),(-s,s),(-s,0),(0,-s),(s,-s)`）。
- canonical 上の座標 = 画像座標に H を適用。

**注意（実物盤の幾何）**: 実物の六角盤は「六角形のマス（ハニカム）」で、石はマスの中心に置かれる。
外枠の六角形はセル中心の六角形より `cell/√3 ≈ 0.577*cell` 外側にある。
一方、アプリから印刷した盤は三角形格子で、外枠が格子の隅点を通る（オフセット 0）。
自動検出した外枠から格子を決めるときは、この2つの慣習（honeycomb / triangular）を
両方試して分類信頼度が高い方を採用する。

## 3. 前処理（v2: グローバル中央値ベースライン）

canonical 画像（RGB, 0..255 float）に対し:

- **ベースライン色 B** = 格子点の六角形（半径 `s*cell`）内部の全画素のチャネル毎中央値（0..255）。
- 追加の空間フィルタはかけない（照明ムラへの頑健性は特徴量の比率とデータ拡張で担保する）。
- Python/JS の一致リスクを避けるため Gaussian 等は使わない。
- **盤外の塗りつぶし**: 実際の盤は紙/板のシルエットが格子より外側にある。辺上の点の石が
  欠けないよう、半径 `(s + 0.6)*cell` より外側だけをベースライン色で埋める（FILL_MARGIN=0.6）。
  Python/JS とも同じ定数を使う。

## 4. パッチと特徴量

- 各点のパッチ: canonical 上の点を中心に、1辺 `0.9 * cell` の正方形を 16x16 にバイリニア間引き。
  - サンプル座標: `u_i = x - side/2 + (i+0.5)*side/16`, `v_j = y - side/2 + (j+0.5)*side/16`
  - 値は RGB 0..255（float）。特徴量計算時は 0..1 に正規化した `rgb[i][j][c]` を使う。
- 特徴量（28次元、`js/photo/features.js` と `dev/photo/train/features.py` で完全一致させる）:

| # | 内容 |
|---|------|
| 0-14 | R,G,B それぞれの mean, std, p10, p50, p90（順: R5, G5, B5） |
| 15-16 | 平均色の HSV の H を cos(2πH), sin(2πH) で表現 |
| 17 | 平均色の S |
| 18 | 平均色の V |
| 19-21 | 外周リング（i<2 or i>=14 or j<2 or j>=14 の平均）− 中央 8x8（4<=i<=11）平均（R,G,B） |
| 22 | 中心(7.5,7.5)から半径6の8方向サンプル（45度刻み, バイリニア）の V の標準偏差 |
| 23 | ハイライト率: V>0.92 かつ S<0.25 の画素の割合 |
| 24-26 | patch 平均_c / (B_c/255) − 1（R,G,B） |
| 27 | 輝度 L=0.299r+0.587g+0.114b の中心差分勾配の大きさの平均（1..14） |

percentile は `sorted[k], k=floor((N-1)*p)`（N=256, 線形補間なし）で統一する。
HSV は標準式（V=max, S=(max-min)/max, H は 0..1）。
勾配（#27）は中心差分を `/2` したもの（`gx=(L[x+1]-L[x-1])/2`）を使う。

## 5. クラス

`0=empty, 1=black, 2=white, 3=red, 4=blue, 5=green, 6=yellow, 7=purple`

## 6. モデル（小型MLP）

- 入力 28 → 隠れ 64 (ReLU) → 32 (ReLU) → 出力 8 (softmax)。パラメータ数 約 6,000。
- 重みは `js/photo/model.json` に `{format:"hexago-photo-mlp-v1", layers:[{W:[[...]], b:[...]}, ...]}` で保存（float32 をそのままJSON）。
- JS 推論: `window.HexagoPhotoModel.forward(features) -> Float32Array(8)`（softmax 済み）。
- 推論速度目標: 127点 < 30ms。

## 7. 出力

各点について `{q, r, cls, conf}`（conf = max softmax）。
信頼度が低い点は UI で強調し、タップで訂正できること。
